# Frontend Folder Structure

```
Frontend/
├── app/                          # App Router
│   ├── layout.tsx                # fonts, ThemeProvider, Analytics
│   ├── page.tsx                  # landing page (+ LivingGraphBackground)
│   ├── globals.css               # Tailwind v4 tokens — the design system
│   ├── not-found.tsx
│   ├── api/
│   │   ├── execute/route.ts      # POST — run code with custom stdin
│   │   └── submit/route.ts       # POST — judge practice submission
│   ├── auth/
│   │   ├── login/ signup/ forgot-password/ reset-password/   # pages
│   │   ├── confirm/route.ts      # PKCE/OTP exchange → session
│   │   └── auth-code-error/      # failure landing
│   ├── dashboard/page.tsx
│   ├── matchmaking/page.tsx      # client page — queue UI
│   ├── onboarding/page.tsx       # server action creates profile
│   ├── problems/
│   │   ├── page.tsx              # list
│   │   └── [slug]/page.tsx       # practice workspace (+ loading/not-found)
│   └── room/[roomId]/page.tsx    # battle workspace (roomId = battles.id)
│
├── middleware.ts                 # session refresh + route guards
│
├── components/
│   ├── ui/                       # shadcn primitives
│   ├── home/                     # landing sections + living-graph-background
│   ├── auth/                     # form components
│   ├── problems/                 # list/card/search/filter/detail
│   ├── workspace/                # WorkspaceShell / ProblemPanel / EditorPane
│   ├── editor/                   # CodeEditor (Monaco), SolverWorkspace, …
│   ├── battle/                   # BattleRoomClient / BattleWorkspace / BattleTimer
│   ├── navbar.tsx …              # dashboard widgets (kebab-case)
│   ├── theme-provider.tsx
│   └── theme-toggle.tsx
│
├── hooks/
│   ├── useWebSocket.ts           # matchmaking socket
│   ├── useBattleSocket.ts        # battle socket
│   ├── auth/                     # useLogin/useSignup/useLogout/…
│   └── use-mobile.ts, use-toast.ts
│
├── lib/
│   ├── judge0/                   # execute / judgeSubmission / compare
│   ├── problems/  battles/  queries/   # data-access helpers
│   ├── starter-code/             # per-language editor templates
│   ├── living-graph/engine.ts    # canvas background engine
│   ├── supabase/admin.ts         # service-role client for scripts
│   ├── websocket.ts              # WS protocol (mirrors server/src/types)
│   └── utils.ts                  # cn()
│
├── utils/supabase/               # client / server / middleware / admin
├── services/auth.service.ts      # supabase auth calls
├── types/                        # problem / language / execution
│
├── scripts/                      # content pipeline (see content-pipeline.md)
│   ├── discovery/ generate/ validate/ seed/ lib/
├── data/
│   ├── problems/<slug>/          # problem.json + testcases.json (15 seeded)
│   ├── existing-problems.json
│   └── pattern-discovery-report.json
│
├── docs/                         # legacy in-repo docs (pipeline-era)
├── public/                       # favicon, placeholders
├── styles/globals.css            # ⚠ legacy, unused — app/globals.css is live
├── next.config.mjs               # turbopack root, ignoreBuildErrors
├── components.json               # shadcn config
└── package.json
```

Conventions:

- **One export per file** in `lib/` helpers, named after the file.
- Server-only code (admin clients, judge0 helpers) never sits inside
  `components/` or `hooks/`.
- Path alias `@/*` maps to `Frontend/` root (tsconfig).
- `data/` is content, not code — regenerated by scripts, reviewed by humans.
